# 一键起节点引擎 · 设计说明（飞书版）

> 适用项目：cross-border-ops-wizard　|　目标版本：v0.3.0　|　日期：2026-06-25　|　状态：设计已定稿，待排实现计划

---

## 一句话目标

拿到一台**新开的境外 VPS**，**一条命令**就把它变成可用的代理节点（xray VLESS Reality）+ x-ui 管理后台 + 团队订阅。任何智能体（Claude Code / Codex / WorkBuddy / OpenClaw）都能通过 SSH 跑同一条命令。

> 「一键」的准确含义：你只需提供 `{节点别名，可选域名}`，其余全自动。中间最多有一步**明确列出的人工云操作**（加 DNS 记录 + 云防火墙放行端口），引擎会自动检测并提示，做完重跑即可。

---

## 它最终长什么样

```text
$ ssh tokyo-2 'bash -s' < node-wizard.sh deploy --alias tokyo-2 --domain node.example.com

✅ 节点就绪  tokyo-2 / node.example.com
   面板：  默认仅本机(127.0.0.1)，SSH 隧道访问；需要时 panel-open 临时开放
   订阅：  https://node.example.com:35178/sub/<随机ID>
   VLESS： vless://...@node.example.com:443?security=reality&flow=xtls-rprx-vision...
   凭据：  已写入 ~/.config/vps-ops/tokyo-2-*.env (权限 600)
   验收：  服务✅ 端口✅ TLS✅ 面板✅ 订阅✅ BBR✅  →  ALL PASS
```

---

## 怎么用：一个引擎，六个子命令

脚本 `node-wizard.sh`，在 VPS 上以 root 运行，纯 bash、不依赖任何智能体的专有能力。

| 子命令 | 作用 |
| --- | --- |
| `deploy` | 全量起节点（**幂等**，可重跑续传） |
| `verify` | 跑验收，输出 PASS / FAIL |
| `panel-open` | **临时**开放公网管理后台（证书 + 账号密码 + 随机路径） |
| `panel-close` | 撤掉公网后台 |
| `links` | 打印订阅 / VLESS 链接 |
| `rollback` | 拆除 deploy 创建的内容，恢复原样 |

**deploy 参数**

- `--alias`（必填）：节点别名，用于命名秘密文件
- `--domain`（可选）：有域名才能开 HTTPS 后台网关 + 团队可导入的订阅链接；不填则纯 IP，后台只走 SSH 隧道
- `--profile lighthouse|generic`：云厂商档案（腾讯轻量需单独在控制台放行端口、网卡 MTU 常为 8500）
- `--role`：自定义角色标签，写进交付文档

---

## 关键机制一：半自动「暂停闸门」

`deploy` 第一步先做 **preflight 体检**：检查域名 A 记录是否指向本机、云防火墙端口是否放行。

1. **没就绪** → 打印精确待办（加哪条 A 记录、控制台开哪几个端口）并**直接退出**；
2. 你手动做完那一步 → **重跑 `deploy`**，因为幂等，零副作用地续传。

> 为什么不「卡住等回车」：智能体经 SSH 跑命令，挂起的交互提示不可靠。「检测→给清单→退出→修好重跑」对各家智能体最稳。

---

## 关键机制二：安全姿态（后台默认不上公网）

这是团队最关心的安全点，结论先行：**有没有域名不是被攻击的关键，后台怎么暴露才是。**

| 模式 | 说明 | 安全性 |
| --- | --- | --- |
| **默认** | x-ui 后台只绑 `127.0.0.1`，公网零暴露；管理走 `ssh -L` 隧道。公网上只剩**抗探测**的 Reality:443 | 最高 |
| **按需** | `panel-open` 临时挂 `https://域名:35178/随机路径/`，证书 + basic-auth + x-ui 登录三层；用完 `panel-close` 撤掉 | 可控 |

> 说明：Reality 协议会「借用」一个真实大站的 SNI 伪装，别人扫你 443 看到的是一次「指向大站的正常 TLS 握手」，不像代理——**这不需要你自己的域名**。域名的价值是「便利」（团队导订阅、浏览器开后台），不是安全本身。真正的风险是公网暴露的后台被扫描爆破，所以**默认就不让后台上公网**。

---

## 起完节点产出什么

- **远端**：`/root/ops-secrets/<alias>.env`（权限 600）
- **本地**：拉回 `~/.config/vps-ops/<alias>-*.env`（权限 600）+ 自动生成 runbook 和敏感交付手册
- **屏幕**：只打印后台入口、订阅链接、VLESS 链接、验收结果——**绝不打印私钥**

---

## 可靠性：幂等 + 回滚

- 每个阶段都先检测现状、只补缺失项；**重跑安全**，也是体检闸门之后的标准恢复方式。
- `rollback` 清掉 deploy 建的服务 / 配置 / 防火墙规则 / 证书，把机器还原。

---

## 验收标准（怎样算「做好了」）

- 干净 VPS 在 DNS + 云防火墙就绪后，一次 `deploy` 达到 `ALL PASS`：服务在跑、Reality 在 443、后台绑本机、BBR/fq 已开、（有域名时）证书有效、订阅链接解析为 `@<域名或IP>:443 security=reality flow=xtls-rprx-vision`。
- 在已部署节点上重跑 `deploy`：无改动，仍 `ALL PASS`。
- DNS / 防火墙没就绪时：打印可执行清单并退出，**不留半成品**。
- `panel-open` 后再 `panel-close`：公网无残留后台监听。
- 任何情况下私钥 / 密码都不进屏幕输出。

---

## 这一版刻意不做（避免过度设计）

- 不做云 / DNS 的 API 全自动（留给后续版本做可插拔适配器）
- 不做多协议 / 多入站（先把 Reality 单入站这条验证过的路走稳）
- 不做后台公网常开
